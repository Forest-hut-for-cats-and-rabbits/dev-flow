# Dev-Flow 自动流水线提示

> 说明：本技能自身的自动触发靠 `description` 匹配，**不保证触发**。要让它每次改完文件必定生效，需配合 `PostToolUse` hook —— 见仓库 README 的「安装」第 2 步。

在编码过程中，**每写完一段代码 / 完成一个方法 / 改完一个文件，就立刻自动输出一段流水线提示**，然后再继续写下一处代码——不要等整个任务结束才总结。

## 触发时机

只要当前在做开发任务（多文件改动、新功能实现、重构、持续编码），每完成以下任一节点，立刻输出一段流水线提示，然后再继续写下一处代码：

1. **完成一个方法 / 函数的编写**
2. **改完一个文件**（即使只改一行）
3. **完成一个逻辑块**（如：加完一个拦截器、写完一个 Service 方法、改完一个配置）
4. **做出一个关键决策**（如：选择用哪种方案、为什么这么改）

## 提示格式

```
=== 流水线 [当前步骤/总步骤] ===
文件：<相对路径>
做了什么：<一句话，说清这段代码的作用>
决策点：<为什么这么写 / 有没有别的选择>
下一步：<接下来要改什么>
```

## 规则

- 提示要**短**，每个节点 3~5 行，不要长篇复述代码。
- 提示插在代码改动**之间**，不要攒到最后。
- 如果任务开始时已经列了计划（todo / plan），流水线步骤编号要和计划对应。
- 整个任务结束后，再给一次**总览**，把所有节点串成一条完整流水线。

## 不触发的情况

- 纯问答、纯解释、不改代码的对话。
- 单行、一眼能看完的微小改动（如改个错别字），可以省略提示。

## 辅助工具

需要回顾本次会话的改动全貌时（例如生成总览前），用 Bash 运行：

```bash
bash ~/.claude/skills/dev-flow/scripts/gather.sh
```

`gather.sh` 参数：`auto`（默认，有暂存看暂存区，否则看未暂存）/ `staged`（只看暂存区）/ `all`（看工作区全部改动）。`MAX_DIFF_LINES` 环境变量控制 diff 截断行数（默认 2000）。
