# 编码结束后的独立测试

在主代理完成代码修改后、最终交付前使用。计划评审中的测试视角只用于完善验收和测试设计，不能代替对最终代码的独立测试。用户使用本技能进行开发时，按技能约定直接启动测试子代理；具体工具、可用权限与用户的后续约束仍以当前客户端为准。不强制切换模型，也不递归创建更多代理。

## 交付可验证的最终代码

给测试子代理必要且准确的材料：

- 原始需求、已确认的范围与验收条件；已有项目规则和测试约定。计划评审确认的场景作为起点，但仍需根据最终实现和实际风险补充。
- 用户报告的原始操作、输入特征、错误现象和已有复现证据；缺失的信息明确标注。本指南与 [测试设计指南](test-design.md) 的可访问路径或必要正文应随委派交给测试代理，不假定它继承了主代理上下文。
- 项目绝对路径、可访问的代码位置、本次改动文件及相关未跟踪文件；说明用户已有改动，避免归属误判。
- 待验证的代码状态。共享工作区时明确主代理暂停业务代码修改；隔离工作区时确认未提交修改、相关新增文件及必要资源已完整同步，不能只测旧 HEAD。
- 已知的运行入口、测试命令和必要环境条件；主代理已运行的检查与环境限制如实列为背景，不代替子代理执行。

交付事实和验收标准，让子代理独立判断覆盖场景；不要暗示必须通过、提供预定结论或把实现本身当作预期行为。不要传递凭据或无关私人数据。

通常一个测试子代理足够。只有多个独立业务确实能分开测试且环境互不干扰时才拆分；共享数据库、服务端口或测试数据的检查顺序执行。测试代理的职责不包括继续分派测试。

## 子代理执行范围

子代理先核对适用项目规则和待测代码，再按 [测试设计指南](test-design.md) 从需求建立覆盖表并分析调用链。明确原始问题、适用的关键异常及受影响回归等必测项；按风险选择边界值、决策表、状态转换、故障注入、批量部分失败、并发／幂等与兼容场景。检查共享方法的其他调用方及直接上下游，不只验证改动行；不机械要求每个任务覆盖所有类别。

优先运行已有相关测试，根据缺口选择能证明行为的单元、接口、集成或用户流程验证。对于 bug，实际重跑用户报告场景；对于新行为，依据需求核对输入、输出、状态与副作用。有效参数但业务前置条件未满足的拒绝路径需要单独考虑；数据库回滚、唯一约束和客户端交互不能仅凭 Mock 测试认定通过。

缺少现成测试时，可在隔离临时目录构造最小复现或行为检查；需要补充持久化回归测试时向主代理给出具体建议，由主代理统一修改后复测。不新增仅重复实现的断言，不为覆盖率数字或工具清单引入无关依赖。

不修改业务代码、删除数据、回滚已有改动或引入真实外部副作用。测试使用项目已有且获授权的测试环境；运行受权限、依赖或服务限制时记录实际阻碍，不修改无关全局配置，不把失败隐藏为跳过。单纯看代码属于静态检查，必须与已执行的运行测试区分。

返回精简报告：

| 内容 | 要求 |
| --- | --- |
| 所测代码 | 项目或副本路径、相关文件及代码状态（`committed`/`uncommitted`/`mixed`）；无法确认同步时说明 |
| 实际检查 | 按 `dev-flow.verification.v1` 记录每条检查，字段定义见 [证据 Schema](evidence-schema.md#dev-flowverificationv1) |
| 业务覆盖 | 复用测试设计指南的覆盖表：场景及必测级别、预期及依据、验证层次与用例／操作、实际状态与证据；包含返回结果、数据变化和副作用，并关联验收条件及检查编号 |
| 发现的问题 | 可复现条件、预期与实际差异、影响和具体代码位置 |
| 未验证项 | 未运行的场景及原因，区分代码失败与环境阻碍；对应检查标为 `not-run`，分别说明客户端、接口和数据库缺口，重要排除项说明依据 |
| 核心问答候选 | 有证据时提供需求关键问题、答案及代码或测试依据，供主代理核对 |

每条检查要么实际执行并留下可访问的日志或结果文件，要么明确标为 `not-run` 并写明原因。不要把静态阅读、计划或不存在的命令写成 `passed`；不要用旧 HEAD 或修复前的日志证明当前代码。主代理收到报告后按 `dev-flow.claims.v1` 核对声明与检查编号，校验脚本报错时先补齐证据再交付。字段与状态规则以 [证据 Schema](evidence-schema.md) 为准。

## 主代理收尾

等待测试结果之前可以整理业务节点与问答，不重复子代理的同一轮测试，也不在被测代码上继续编辑。按原始需求核对覆盖表，检查原始问题、关键异常和受影响回归是否实际执行，不能只看测试套件的退出码。报告有含糊结论或缺少证据时，要求子代理补充具体场景、命令或结果。

确认问题属于本需求后修复，再把修复后的代码交给同一测试子代理复测相关场景；是否扩大回归范围取决于实际影响。相关代码修改后，旧结果不能证明新实现。已有测试未覆盖的限制应保留，不以重复运行无关检查代替覆盖。

最终由主代理核对业务节点、代码依据和问答，将主代理自检、子代理动态测试、静态检查及环境阻碍分开说明。当前客户端无法启动子代理时明确“未完成独立测试”，继续可执行的主代理检查，不虚构代理或执行证据。

任何适用必测项失败或未执行，整体结论保留“失败”或“验证不完整”，同时列出已通过范围；不以其他用例通过、代码覆盖率较高或后端测试通过覆盖剩余缺口。相关检查通过且没有新变化或未解决疑点时结束，不为扩大数量重复测试。
